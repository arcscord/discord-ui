# Vue

`@arcscord/discord-ui-vue` is the native Vue adapter. It requires Vue 3.5 or later
in the Vue 3 line. The core and adapters have independent versions.

## Installation

Use the package name to install the version selected by npm's `latest` tag.
Check [npm versions](https://www.npmjs.com/package/@arcscord/discord-ui-vue?activeTab=versions)
to choose a specific release.

```sh
pnpm add @arcscord/discord-ui-vue
```

Import `@arcscord/discord-ui-vue/styles.css` once. It is complete; no React, Tailwind,
global reset, remote font or additional core CSS import is required.

To test local builds, install the Vue tarball and point a `pnpm-workspace.yaml`
override for `@arcscord/discord-ui-core` at the matching Core tarball.

## Events and controlled selections

Callbacks become typed Vue events. `SelectMenu` uses `v-model:values`; absent
values use local state, while an empty array is an explicitly controlled empty
selection. The application updates message reactions and other persisted data.
On `Message`, use `:select-values` for a map keyed by component ID.
`@select-change` reports the component ID, selected values and message
context so the host can update that map.

## Channels, commands and threads

`ChannelComposer` uses `v-model`. `ChannelView` supports
`v-model:active-thread-id`; omit the prop for local navigation or pass `null` to
close a controlled thread. `send`, `thread-send` and `slash-command` report intent;
the host updates channel data. An absent send listener preserves read-only behavior.

## Slots and content

Children become the default slot. Named slots replace the React content props.
`Button.variant` selects its appearance. Vue's `style` and `class` remain ordinary
attributes. Give buttons with only an emoji an accessible `aria-label`.
Use `:render-code="renderHighlightedCode"` to opt into syntax highlighting
through the separate `./highlight` entry.

See the [complete Vue API](/docs/vue/api) for every component, prop, event and slot, and
[SSR and hydration](/docs/vue/ssr) for server integration. All three themes, custom token
inheritance, labels, locale/time zone, blocked remote media and image fallbacks
use the shared core policies. Nuxt and other frameworks are not validated here.

## Author and mention callbacks

`Message`, `MessageList`, `ChannelView` and `ThreadPanel` expose author, mention
and message-context callbacks. The first argument is `MessageAuthor`,
`MentionTarget` or `MessageView`; the second is a native DOM `MouseEvent`.
`MentionTarget` carries `id`, `kind`, `name` and optional `color`, including
unresolved mention IDs. Reply authors and mentions inside rich content use the
same handlers. The application owns profile cards and menus.

```vue
<Message :message="message"
  @user-click="(author, event) => showProfile(author, event)"
  @user-context-menu="(author, event) => openUserMenu(author, event)"
  @mention-click="(mention, event) => showMention(mention, event)"
  @mention-context-menu="(mention, event) => openMentionMenu(mention, event)"
  @message-context-menu="(record, event) => openMessageMenu(record, event)" />
```

User and mention context handlers take priority over the message handler.
Call `event.preventDefault()` in your host callback when replacing the browser
context menu. Restore focus when dismissing your interface. Standalone `Author`,
`Avatar`, `MessageHeader` and `ReplyPreview` accept user handlers; `Mention` accepts
an optional ID and mention handlers, and `Markdown` accepts mention handlers.
