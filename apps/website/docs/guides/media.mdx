# Images, video, audio and stickers

Use `Media` for an image or video, `MediaGallery` for a mixed gallery, `Audio`
for an audio attachment or voice note, `Sticker` for a sticker and `File` for a
file card. Video and audio models select their player explicitly.

## API reference

[DiscordUI](/docs/api/display-components#discordui), [File](/docs/api/interactive-components#file), [MediaGallery](/docs/api/display-components#mediagallery).

## Supply assets and dimensions

A `MediaView` requires `id`, `url` and `alt`; `width` and `height` are optional.
`MessageMediaView` also accepts `VideoView`, identified by `kind: "video"`.
Dimensions reserve space and describe aspect ratio. Give every gallery item a
stable ID. For a classic message, use `media` and `attachments`; in a V2 body use
media-gallery and file nodes inside the component tree. V2 galleries accept
images and videos. Message-level audio attachments and stickers belong to classic
messages. V2 file components retain their file-link rendering, including when their source is audio.

The minimal example uses `/examples/landscape.svg`. Copy
`apps/website/static/examples/landscape.svg` into your app's public `examples`
directory, or replace the path with your own asset. The report link is an
illustrative HTTP(S) URL, not a downloadable fixture provided by the library.
`FileView.size` is already formatted text, such as `24 KB`, not a byte count.

## Spoilers and failures

Set `spoiler: true` on an image, video, audio attachment or file to hide it behind a reveal control.
Spoiled media is not mounted until revealed. Width and height help the concealed
image preserve its aspect ratio. A text spoiler conceals already-rendered text.

Blocked, invalid or failed images show a localized unavailable state associated
with the image alternative. Avatars and selected-user chips have their own initial
fallbacks. Revealing content is local UI state, not authorization.

## Remote media policy

`DiscordUI.allowRemoteMedia` defaults to `true`. Set it to `false` to block
explicit HTTP(S) media sources, including video, audio and stickers, across avatars, emoji, galleries, embed images
and icons, reply and thread avatars, and select-menu avatars. Use
`remoteMediaAllowlist` to make exceptions. For example, allow the Discord
emoji directory while leaving Discord avatars and attachments blocked.

```tsx
<DiscordUI
  allowRemoteMedia={false}
  remoteMediaAllowlist={["https://cdn.discordapp.com/emojis/"]}
  entities={{
    emojis: {
      "456789012345678901": {
        name: "dance",
        image: "https://cdn.discordapp.com/emojis/456789012345678901.gif",
      },
    },
  }}
>
  <Markdown content="<a:dance:456789012345678901>" />
</DiscordUI>
```

Each entry is an absolute HTTP(S) origin, a directory ending in `/`, or an
exact path on that origin. The scheme, hostname and port must match. Omit
queries and fragments from the entries. An image URL can still include a
query such as `?size=48`. Custom emoji images come from the host's display
data. The [Vue media guide](../vue/media.mdx) demonstrates this policy with
an interactive Vue example.

Root-relative paths (a single leading slash without backslashes), HTTP(S) blob
URLs, and supported base64 PNG/JPEG/GIF/WebP image data remain accepted. Protocol-
relative URLs and executable schemes are rejected. Absolute same-origin image
URLs also require remote media permission. Use root-relative paths for local
assets. Supported image data formats exclude SVG.

File download links, ordinary Markdown links and link buttons still use their
separate HTTP(S) link policy. The image policy checks the initial source URL.
Redirects and other network requests are governed by the browser and the
host application.

## Video and audio players

`Video` accepts a `video` model with `kind: "video"`, `id`, `url` and `alt`.
Optional dimensions reserve space, `posterUrl` supplies a policy-checked poster
and `durationSeconds` supplies the initial duration. `Audio` accepts an `audio`
model with `kind: "audio"`, `id`, `url` and `name`; `size` is display text.
The same models work in `message.media` and `message.attachments` respectively.

Playback starts on user interaction. Audio players use `preload="none"`. Video
with a supplied poster also uses `preload="none"`; without a poster it loads
metadata to expose its first frame. This can request video bytes before a click,
subject to the same remote-media policy as the poster and source. The initial video preview shows a central
play button. Its translucent playback bar appears after playback starts.
Players expose
keyboard-accessible play/pause, seeking, volume and mute controls. Hover or focus
the speaker to open its vertical volume slider. Escape closes it and returns focus
to the speaker. Audio files show a file icon, their name and a separate size label.
Audio files and videos expose a top-right download link on hover or keyboard
focus. Its URL must satisfy the HTTP(S) link policy. Root-relative media resolves
to its same-origin HTTP(S) source for downloading. Voice notes omit this action. Video adds
fullscreen where supported. Duration and progress follow the browser's media
events. The browser determines which codecs it can decode.

For a vocal, set `voice: true`. Supply optional `waveform` samples between 0 and 1
and `durationSeconds`. The compact vocal layout places its waveform behind the
seek control and shows one duration. Missing samples use a simple progress bar.
Vocals also expose 1X, 1.5X and 2X playback speeds. Control names can be translated through
`DiscordUI.labels`. Blocked or failed media show the localized unavailable state.
After a playback error, allowed audio files and videos retain a download link so
the attachment can be opened externally. Voice messages retain their compact error state.

## Stickers

`Sticker` accepts a `sticker` model with `id`, `name`, `format` and `url`.
Use `png`, `apng` or `gif` for browser-rendered stickers. The name provides its
accessible alternative. `lottie` displays a localized unsupported-format state.
Classic messages accept these models in `stickers`.

`fromDiscordMessage` converts received image, video and audio attachments, voice
metadata and sticker items. `fromDiscordMessageComponents` also converts videos
in V2 galleries. These helpers use supplied API data and make no Discord requests.
The local example uses synthetic `/examples/trail.webm` and `/examples/trail.wav`.
The video uses `/examples/trail-poster.png`, extracted from its first frame.
Its `/examples/arcscord-sticker.png` sticker uses the supplied Arcscord logo unchanged.
Copy these assets or supply your own URLs.

## Migrating existing media consumers

`MediaView` keeps its image contract. `MessageContentView.media` and
`GalleryView.items` now contain `MessageMediaView` values, so custom renderers
must handle videos as well as images. Narrow with `"kind" in item && item.kind === "video"`,
or delegate to `Media` or `MediaGallery`. The discriminator value identifies a video.

`MessageContentView.attachments` now contains `FileView | AudioView` values.
Custom attachment renderers should check `attachment.kind === "audio"` and render
`Audio` for that branch before passing file values to `File`.

`fromDiscordMessage` now classifies recognized audio attachments as `AudioView`
and moves recognized video attachments into `media`. Consumers that previously
assumed every attachment was a generic file need to update their rendering and
any attachment filtering logic. Unknown formats continue to produce generic files.

## File links

Files expose a name link and a download control only for allowed HTTP(S) URLs.
Unsafe file URLs leave the name as text. Relative file paths do not satisfy that
link policy; resolve your file endpoint to an explicit HTTP(S) URL. The browser
and remote server determine download behavior; a download attribute does not
promise cross-origin downloading.
