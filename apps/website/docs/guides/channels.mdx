# Channels and message history

`ChannelView` combines a header, scrolling message list, composer and loaded
thread navigation. `MessageList` renders just an ordered history in your own layout.

## Supply ordered snapshots

A `ChannelViewModel` has `id`, `name`, optional `topic`, `messages` and optional
`threads`. Array order is render order: there is no sorting, pagination, Discord
fetch or virtualized history API. Add messages by returning a new snapshot.
`MessageList` can add date separators using the wrapper time zone; invalid
message timestamps do not create a date separator. An empty history shows the
translated empty-channel label.

The minimal example deliberately uses fixed timestamps and deterministic IDs
within its local list. For an actual application, assign persistent IDs and
authoritative timestamps when an event is received or created, outside rendering.

## Composer and layout

`onSend(content)` reports the text; append a message yourself. The built-in channel
composer clears its local draft after a handled send. `composer={false}` hides it;
`composerDisabled` disables it; `composer` and `header` accept custom React nodes.
A `MessageList` has no composer or viewport and should live in your own container.

`ChannelView` adds a default `DiscordUI` wrapper when used outside a scope. Supply
an explicit wrapper to share the intended theme, locale, labels and entity maps.
The default height is 560; the minimal example uses 320.

## Scrolling behavior

`autoScroll` defaults to `true`. Opening a conversation or changing the last message
ID scrolls to the bottom and re-enables following. Therefore an appended message
can move a reader who had scrolled upward. Size changes, such as an image loading,
follow the bottom only while the reader remains within 24 pixels of it.

Set `autoScroll={false}` to opt out of this automatic positioning. Use `MessageList`
in your own scrolling layout when you need application-specific pagination,
anchoring or unread behavior. The documentation website has its own page-scroll
chaining override; it does not redefine library history defaults.

## Conversation identity

Changing `channel.id` remounts channel-local draft, selections and thread navigation.
Controlled selections remain in the application. Use an external draft store and
a custom composer if drafts must survive conversation switches. See
[threads](./threads.mdx) for the parent/thread links needed to open loaded panels.
