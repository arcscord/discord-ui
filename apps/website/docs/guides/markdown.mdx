# Markdown, mentions and emoji

Use `Markdown` directly or `body: { kind: "markdown", content }` inside a message.
The renderer builds React elements from parsed content; it does not inject raw HTML.

## Supported content

| Content | Behavior |
| --- | --- |
| Bold, italic, underline, strikethrough | Inline formatting from Discord-style syntax |
| Inline code and fenced code | Escaped code; plain code blocks unless a renderer is supplied |
| Headings, subtext and block quotes | Block presentation; heading levels are limited to 1–3 |
| Bullet and numbered lists | Simple consecutive list blocks; ordered lists retain their start number |
| Spoilers | Local reveal/hide buttons, with concealed text inert while hidden |
| HTTP(S) links | Open externally with protected opener relationship |
| User/channel/role mentions, everyone/here | Display tokens using resolved names where supplied |
| Custom emoji, Unicode emoji, slash-command mentions | Displayed using available metadata |
| Discord timestamp tokens | Explicit locale, time zone and reference-time formatting |

This is a Discord-oriented renderer, not a full HTML or general Markdown engine.
Simple lists are not a promise of arbitrary nested-list or table support.
Intentional blank lines are retained around block content.

## Resolve entities

Pass lookup maps through `DiscordUI.entities`: `users`, `channels` and `commands`
map string IDs to display names; roles can also carry a color. `emojis` map IDs to
`{ name, image }`. Missing user/channel/role metadata falls back to the ID; custom
emoji uses its parsed name when no image is provided. Mentions are display tokens,
not live Discord navigation or permission checks. Use full Discord snowflake IDs
in parsed mention tokens; short placeholder IDs such as `<@42>` remain plain text.

Unicode emoji use Twemoji images when remote media is enabled, with native text
as the failed-image fallback. Disabling remote media keeps Unicode as text. Custom
image emoji also follow the shared media policy. See [media handling](./media.mdx#remote-media-policy).

## Code and links

Opt in to code highlighting by importing `renderHighlightedCode` from
`@arcscord/discord-ui/highlight` and supplying it as `DiscordUI.renderCode`.
Its registered languages are JavaScript, TypeScript, JSON, CSS, Bash and Python;
unknown languages fall back to escaped code. The root entry does not enable it.

Outgoing links require explicit HTTP(S) URLs. Unsafe or unsupported targets retain
their label without an active anchor. Content is not a channel for injecting
HTML; your application must also validate any custom renderer it supplies.

For relative timestamps in standalone Markdown, set `referenceTime` explicitly.
[Localization](./localization.mdx) explains formatting and deterministic fallbacks.
