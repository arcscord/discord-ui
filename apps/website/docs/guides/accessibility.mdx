# Accessibility

Preserve the semantics and focus behavior of the supplied controls when composing
a custom interface. Accessibility also depends on your labels, content, layout
and application behavior.

## Verify keyboard operation

| Control | Expected interaction |
| --- | --- |
| Button/reaction/spoiler | Tab focus; Enter or Space activates |
| Select menu | Arrows navigate, Enter selects, Escape dismisses; entity menus allow text search |
| Composer | Enter sends; Shift+Enter adds a newline; IME composition is respected |
| Command suggestions | Arrows navigate; Enter or Tab selects; Escape hides suggestions |
| Thread panel | Close control and Escape request closing; integrated navigation restores opener focus |

A focused control must remain visible and reachable in narrow layouts. Check open
menus near viewport edges, scrolling histories, long labels and disabled states.
Do not remove focus outlines in application CSS. Do not interpret screenshot-only
inspection as proof of keyboard support.

## Label content and state

Provide meaningful image `alt` text and distinct button labels. Translate the
labels of the controls actually used, including reveal/hide, unavailable media,
selection removal and empty history. Reaction buttons expose `aria-pressed`;
selects expose selection state; spoiler buttons expose `aria-expanded`.

Hidden text spoiler content is inert, and media spoilers defer mounting content
until reveal. When an application dismisses an ephemeral message or removes a
focused control, place focus on a sensible remaining control. Standalone thread
layouts also own focus restoration after closing.

The minimal example announces a local review result through `role="status"`.
Real applications must choose useful live announcements without making every
message update noisy. Channel/thread histories already provide log semantics.

## Application-level review

Test realistic content in Light/Ash/Dark, narrow and zoomed layouts, and your target
browser/assistive-technology combinations. Token overrides can reduce contrast;
model validity does not validate contrast or accessibility. The repository's narrow
Chromium checks are viewport tests, not real-device or screen-reader certification.
Honor reduced-motion preferences in any animations your application adds.
